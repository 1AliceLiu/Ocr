# 从平台拉取全部设备名和视频流（新手版）

> 适用：大华 EVO / 智能物联综合管理平台 iConnection Center V5.0.6+（`/evo-apigw/...`）
> 配套脚本：`scripts/evo_pull.py`、`scripts/evo_stream_url.py`
>
> 本文已在 `https://cloudstorage.mediumvis.com:8092` 实测通过：
> 2083 台设备、2189 个通道，**1521 路在线视频通道全部取流成功**；
> 4 个流媒体端口 `9100/9104/9108/9112` 都返回 RTSP `200 OK` + SDP，
> ffprobe 实际解码出 H.264 640x480。

---

## 0. 先弄懂三件事，不然一定会在半路卡住

### 0.1 平台有三套接口，文档只给了其中一套

| 接口族 | 路径前缀 | 作用 | 文档位置 |
|---|---|---|---|
| 登录 | `/evo-apigw/evo-oauth/1.0.0/oauth/...` | 用账号密码换 `access_token` | 鉴权认证 |
| 业务资源 | `/evo-apigw/evo-brm/...` | 组织、设备、通道的查询 | 设备详情/分页/树/通道分页 |
| 流媒体 | `/evo-apigw/admin/API/MTS/...` | 取 RTSP/HLS/FLV 播放地址 | 视频应用（常见问题） |

所以：**设备树/设备分页/通道分页只能告诉你“有哪些摄像头”，不能给你视频流。**
取流要另外调流媒体接口。这是新手最容易误解的地方。

### 0.2 数据模型（从大到小）

```
平台
└─ 组织 (ownerCode, 如 001 / 001001)          ← 决定账号能看到哪些设备
   └─ 设备 (deviceCode, 如 1000014)           ← 一台录像机/摄像机/门禁
      └─ 单元 (unitType, 如 1=视频单元)
         └─ 通道 (channelCode, 如 1000014$1$0$0)  ← 一路视频 = 一个通道
```

- 你最终要的“视频流”，单位是**通道**，不是设备。
- `channelCode` 的格式固定是 `设备编码$单元类型$单元序号$通道序号`，例如 `1000014$1$0$0`。
- 一个设备可能有多个通道（多镜头 NVR 很常见）。

### 0.3 认证方式

所有业务接口都要在请求头带：

```
Authorization: bearer <access_token>
```

- 规则是 `token_type + 空格 + access_token`，`token_type` 固定为 `bearer`。
- ICC 的 `access_token` 本身通常带前缀，例如 `1:704dc1bc-...`，所以请求头看起来是
  `bearer 1:704dc1bc-...`，**不要把 `1:` 去掉**。
- 鉴权 token 一般 30 分钟过期，脚本会用 `refresh_token` 自动续期。
- 注意区分：**鉴权 token** 和**取流 token** 是两回事。取流 token 只活约 30 秒，
  且只能使用一次（见第 5 节）。

登录失败时最常见的报错是 `Wrong public key`：公钥默认 10 分钟过期且登录成功后失效，
重新取一次公钥即可；另外 `password` 必须是 RSA 加密后的密文。

## 2. 第 1 步：确认平台地址和账号

问管理员要三样东西：

- 平台地址，例如 `https://10.0.0.10:8090`
- 一个能看全部摄像头的账号、密码
- 账号绑定的组织（如果只能看到部分设备，多半是组织权限问题）

先用浏览器登录一次，确认能看到“设备管理 / 实时预览”，再往下做。

## 3. 第 2 步：拿到 token（两种方法，任选）

### 方法 A：从浏览器直接抄（最简单，推荐先做这个）

1. 浏览器打开平台，按 `F12` 打开开发者工具，切到 **Network（网络）**。
2. 退出账号再重新登录。
3. 在请求列表里找名字含 `oauth/token` 的请求，点开：
   - **Response** 里找 `access_token`，复制整段；
   - 或看 **Headers → Request Headers → Authorization**，复制 `bearer ` 后面那段。
4. 顺便记下登录响应里的 `userId`（脚本的 `--user-id`）。

用抄来的 token 直接跑了试试（不用给密码）：

```powershell
python scripts\evo_pull.py --base https://10.0.0.10:8090 `
  --token "把token粘在这里" --user-id 1 --probe
```

### 方法 B：让脚本自己登录

```powershell
python scripts\evo_pull.py --base https://10.0.0.10:8090 `
  --user admin --password '你的密码' --probe
```

脚本的登录流程和网页一致：先取平台公钥，用 RSA 加密密码，再 POST 到
`/evo-apigw/evo-oauth/oauth/token`。不同版本路径可能多个 `/1.0.0`，脚本会自动试。

`--probe` 会依次检查：地址是否通 → 能否登录 → 设备分页/通道分页/设备树是否可用，输出类似：

```
base: https://10.0.0.10:8090
  GET /                      HTTP 200
  public key                 /evo-apigw/evo-oauth/oauth/public-key
  token                      ok (1234 chars)
  device page                ok=True rows=1
  channel page               ok=True rows=1
  device tree                ok=True rows=1
```

只要这三行 `ok=True`，说明接口和权限都没问题，可以继续。

## 4. 第 3 步：导出设备名和通道名

```powershell
python scripts\evo_pull.py --base https://10.0.0.10:8090 `
  --user admin --password '你的密码' --outdir out
```

会得到两个文件（UTF-8 BOM，Excel 可直接打开）：

- `out/devices.csv`：设备编码、设备名称、IP、厂商、在线状态、所属组织
- `out/channels.csv`：通道编码、通道名称、所属设备、通道序号、在线状态、组织路径

脚本内部做的事，对应你贴的文档：

1. **`POST /evo-apigw/evo-brm/1.2.0/device/subsystem/page`**
   每页最多 1000 条，`pageNum` 从 1 递增，读到 `currentPage == totalPage` 为止。
   参数 `showChildNodeData: 1` 表示包含子组织设备。
2. 如果设备分页不可用（有的版本没开这个接口），自动退回
   **`POST /evo-apigw/evo-brm/1.0.0/tree`**，从根组织 `001` 开始逐层递归，
   取 `nodeType=dev` 的节点。
3. **`POST /evo-apigw/evo-brm/1.2.0/device/channel/subsystem/page`** 拿通道；
   失败时再用**设备详情** `/device/{deviceCode}` 里的 `units[].channels[]` 兜底。

> 注意文档里的一个坑：evo-brm 的成功码是 `"code": "0"`，而流媒体 MTS 接口
> 的成功码是 `"code": "1000"`。用同一个判断函数会误判，脚本里已经区分。

如果设备/通道数是 0：

- 换 `--source tree` 再试；
- 检查账号组织权限；
- 组织是逻辑组织时，根节点不是 `001`，而是 `L` 开头，需要先调“用户详情”拿
  `defaultOrgCode`，再用 `--root L02`。

## 5. 第 4 步：取视频流（关键一步）

### 5.1 先搞清楚：平台怎么把流给网页

在平台网页打开 **实时预览**，播放一路摄像头，F12 → Network，过滤 `StartVideo` /
`stream` / `rtsp`，你会看到类似：

```
POST /evo-apigw/admin/API/MTS/Video/StartVideo
body: {"data":{"dataType":"3","streamType":"2","channelId":"1000014$1$0$0",
               "urlType":1,"packtype":"Private","optModule":"ADMIN_001031"}}
```

响应里通常有：

```json
{"code":"1000","data":{
  "url":"rtsp://1.2.3.4:9104/dss/...|rtsp://内网地址:9104/dss/...",
  "token":"abc123",
  "session":"123456789"
}}
```

- `url` 通常用 `|` 拼了两个地址：**内网**（如 `172.16.100.2:9100`）和**公网**
  （如 `118.140.234.166:9108`）。脚本会对每个地址做 TCP 连通性测试，自动选你这台
  电脑真正能连上的那个。
- `token` 要拼到 URL 后面：`...?token=1823105`。
- `session` 是这次取流会话，调用 `StopVideo` 释放。
- **只对 `unitType=1`（视频单元）取流**。`unitType=3/4` 是报警输入/输出，
  对它们调 `StartVideo` 会失败（本次实测 65 个这类通道全部失败，属于正常现象）。
- **RTSP 的 token 只活约 30 秒，而且只能用一次**：播放成功一次后服务端立即作废，
  第二次会返回 401（VLC 会弹用户名密码框）。所以**批量保存的 live 地址基本没用**。
- HLS/FLV 的 token 有效期是 2 小时（5.0.12 及以上版本必须拼）。
- 端口：RTSP 实时流 `9100`、回放 `9320`；HLS `7086/7096`；FLV `7886/7896`；
  RTMP `1975`。防火墙没放这些端口，地址再对也播不了。
- VLC 若提示输入用户名密码，在地址后加 `trackID=0`，并把
  “输入/编解码器 → live555 → RTP over RTSP (TCP)”打开。

### 5.2 批量采集：用 template 模式

```powershell
python scripts\evo_pull.py --base https://10.0.0.10:8090 `
  --user admin --password '你的密码' --outdir out `
  --with-streams --stream-mode template --delay 0.1
```

| 模式 | 输出 | 用途 |
|---|---|---|
| `template`（默认） | `rtsp://...?token=<TOKEN>` | **批量采集用这个**；记录地址形态，token 现取现用 |
| `live` | 带真实 token 的地址 | 只适合马上播放；超过 30 秒就失效 |

`template` 模式每取完一路会立即 `StopVideo` 释放会话，不会把平台会话占满。
`live` 模式默认保留会话，加 `--stop-sessions` 才会释放。

### 5.3 真正播放前：按需换一个新 token

因为 token 只能活 30 秒，正确做法是**播放前 1 秒再取**：

```powershell
python scripts\evo_stream_url.py --channel '1003060$1$0$0' --stream-type 2
```

输出一行可直接播放的地址。你的 OCR/录像程序应该在每次 `cv2.VideoCapture` 或
`ffmpeg` 启动前调用它，而不是复用批量导出的旧地址。

`--stream-type 1` 是主码流（清晰、带宽高），`2` 是子码流（流畅、带宽低）。
批量 OCR 建议先用 `2`。

### 5.4 如果 StartVideo 不存在 / 返回 404

说明你这套平台的流媒体服务不是 MTS。处理方法：

1. 在网页里播放一路视频，F12 → Network，把真正返回播放地址的请求找出来
   （常见关键字：`stream`、`play`、`realmonitor`、`m3u8`、`flv`、`ws`）；
2. 把它的 **Method、URL、请求体** 记下来；
3. 改 `scripts/evo_pull.py` 顶部的 `START_VIDEO` 和 `fetch_streams()` 里的请求体。

常见返回形态和对应播法：

| 返回 | 用什么拉 |
|---|---|
| `rtsp://...` | `ffmpeg -rtsp_transport tcp -i ...` |
| `http://.../xxx.m3u8` | `ffmpeg -i http://.../xxx.m3u8 -c copy` |
| `http://.../xxx.flv`（HTTP-FLV） | `ffmpeg -i http://.../xxx.flv -c copy` |
| `ws://...`（WebSocket-FLV） | 需要先转封装，或让平台开 HLS/RTSP |

> 如果平台支持 GB28181 或自带 RTSP 网关，也可以绕开这套 API：
> 摄像机的国标通道编码（`deviceSn`）通常能直接映射成 RTSP 地址，稳定性更好。

## 6. 第 5 步：本地验证播放和录制

> 本机检测到还没装 ffmpeg（`ffmpeg -version` 找不到命令）。任选一种安装：
> `winget install Gyan.FFmpeg`，或从 gyan.dev 下载解压后把 `bin` 目录加进 PATH。

播放（有画面就说明通了）：

```powershell
ffplay -rtsp_transport tcp "把 streams.txt 里的地址粘这里"
```

录 60 秒存成 mp4：

```powershell
ffmpeg -rtsp_transport tcp -i "rtsp://..." -t 60 -c copy test.mp4
```

持续录制并按 10 分钟切片：

```powershell
ffmpeg -rtsp_transport tcp -i "rtsp://..." -c copy -f segment `
  -segment_time 600 "rec_%Y%m%d_%H%M%S.mp4"
```

常见报错：

- `Connection refused / timed out`：URL 里是内网地址，或流媒体端口没开放；
- `401 Unauthorized`：token 过期或没拼上去；
- `method DESCRIBE failed: 454`：会话已失效，重新调 StartVideo 换地址；
- 画面卡顿：加 `-rtsp_transport tcp`，并改用子码流（`streamType=2`）。

## 6.5 一次看完全部通道：快照图片墙

1521 路同时实时播放不现实（带宽约 3 Gbps，单机也解不了这么多路）。
更实用的办法是**每路抓一帧**，生成一个网页图片墙：

```powershell
# 先抓 20 路看效果
python scripts\evo_snapshot.py --limit 20 --workers 4

# 确认后抓全部（已完成的不重复抓）
python scripts\evo_snapshot.py --workers 8 --skip-existing
```

输出：

```
snapshots/
├─ index.html      ← 浏览器打开：start snapshots\index.html
├─ report.csv      ← 每路成功/失败、错误原因
└─ images/
   ├─ 0001_1003060_1_0_0.jpg
   └─ ...
```

要点：

- 每一路都会**现取一个新 token**，抓完立即 `StopVideo`，不复用旧地址；
- 4 并发约 1 秒/路，全量 1521 路约 30 分钟；8 并发约 15-20 分钟；
- 图片默认缩放到宽 480，可用 `--width` 调整；
- 失败的路不会中断整体，最后看 `report.csv` 的“错误”列；
- 重复运行加 `--skip-existing`，只补缺失/失败的通道。

## 6.6 用 compose 管理 OCR 抓帧服务

`compose.yaml` 里新增了 `osd20` 服务：每 60 秒抓一次前 20 路 1080p 主码流，
识别左下角数字，结果追加到 `output.txt`，并按轮次记录到 `output/osd_rounds.csv`。
最新帧覆盖保存在 `snapshots/osd20/`。

```powershell
# 启动 / 停止 / 重启
docker compose up -d osd20
docker compose stop osd20
docker compose restart osd20

# 看状态和日志
docker compose ps osd20
docker compose logs -f --tail 50 osd20
```

账号和间隔写在 `.env`：

```
EVO_BASE=https://平台IP:端口
EVO_USER=system
EVO_PASSWORD=密码
OSD_INTERVAL=60
```

服务内部用 `imageio-ffmpeg` 自带的 ffmpeg 取帧（容器里不需要另装 ffmpeg CLI），
`Dockerfile.dev` 已加入 `cryptography` 和 `imageio-ffmpeg`，重建镜像后依然可用。

`docker compose stop` 之后容器不会自动拉起；`docker compose up -d osd20` 可再次启动。

## 7. 第 6 步：接到你现有的 OCR 流程

你仓库里已有的链路是：

```
scrape_mediumvis_rtsp.py  →  rtsp_streams.txt  →  web-spider-label.txt
                                             →  rtsp_osd_monitor.py（抽帧 + OCR）
```

新脚本产出的 `out/streams.txt` 列顺序是：

```
编号  通道编码  设备编码  通道名称  通道序号  组织  状态  RTSP地址
```

要喂给 `rtsp_osd_monitor.py`，只需生成 `<期望编码> <rtsp>` 两列。
例如用通道名称里的编号前缀，或直接人工确认后生成：

```powershell
# 示例：取第 1 列编号 + 第 8 列地址（按你的实际编号规则调整）
Get-Content out\streams.txt |
  Where-Object { $_ -notmatch '^#' -and $_ -match '\t' } |
  ForEach-Object { $f = $_ -split "`t"; "$($f[0]) $($f[7])" } |
  Set-Content web-spider-label.txt -Encoding utf8
```

如果每路都要独立、长期可用的流，建议在本地做一次 **RTSP 转 RTSP/RTMP/HLS 的转发**
（ffmpeg 或 mediamtx），再把转发后的固定地址给 OCR 脚本，避免平台 token 过期。

## 8. 常见问题速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `success=false, code=28****` | 无权限 / 参数错 | 换有权限的账号，检查组织编码 |
| 设备分页 0 条 | 组织权限或版本不支持 | `--source tree`；确认 `ownerCode` |
| `code=27001007` / 401 | 鉴权 token 过期 | 脚本会自动刷新；手动跑就重新登录 |
| 通道有、流没有 | 设备离线 / 未接入 | 看 `isOnline`、`access` 字段 |
| URL 是内网 `172.16.x`，连不上 | 平台同时返回了内外网地址 | 脚本会自动做 TCP 探测选可达地址；两个都不通就找管理员要端口映射 |
| 取流几十路后大量失败 | 平台并发/会话上限 | 降 `--delay` 到 0.3~1 秒，分批跑 |
| 中文乱码 | 终端编码 | CSV 用 Excel 打开；PowerShell 执行 `chcp 65001` |

## 9. 安全提醒

- 密码、token、流地址都等于平台控制权，**不要提交到代码仓库或发群里**。
- 不要在命令行里直接写密码（会留在 PowerShell 历史），改用环境变量：

  ```powershell
  $env:EVO_BASE = 'https://平台IP:端口'
  $env:EVO_USER = 'system'
  $env:EVO_PASSWORD = '密码'
  python scripts\evo_pull.py --outdir out --probe
  ```

  两个脚本都支持 `EVO_BASE` / `EVO_USER` / `EVO_PASSWORD`。
- 只拉你有权限的设备，控制并发，别把生产平台打满。
- `--verify-tls` 在自签名环境关闭是妥协，内网长期使用最好给平台换正式证书。
